# نقشهٔ راه حرفه‌ای ربات بله (`balebot`)

> سند زنده — هر فاز پس از تست و پوش، تیک می‌خورد.

---

## ۱) چشم‌انداز

ربات بله از یک «منوی سادهٔ مأموریت» به **دستیار عملیاتی کامل سامانهٔ حضور
و غیاب** تبدیل شود:

- کارمند در بله همهٔ کارهای روزمره‌اش را انجام دهد (بدون باز کردن سایت).
- مدیر از هر جا (موبایل) سامانه را کنترل کند.
- اعلان‌ها و یادآورها خودکار باشند.
- همهٔ اقدامات حساس **قابل ردیابی (Audit)** باشند.
- ربات در برابر خطای شبکه، پیام تکراری، سوءاستفاده و قطعی مقاوم باشد.

## ۳) معماری هدف

```
Bale API
   │  long polling / webhook
   ▼
transport  ──►  router  ──►  middleware
                               ├─ auth / linked?
                               ├─ role guard
                               ├─ rate limit
                               ├─ bot enabled?
                               └─ audit
                                   ▼
                               handlers
                                   ▼
                               services  ──►  models (Django ORM)
                                   │
                                   ├─ notifications / reminders
                                   ├─ Excel export
                                   └─ reports
```

اصول:

1. **هیچ قانون کسب‌وکاری در handler نوشته نشود** — همه در `services` یا
   ماژول‌های موجود سایت (`errands.forms`, `recognition.reports`).
2. **تنظیمات در دیتابیس** (`BotConfig`) تا بدون دیپلوی قابل تغییر باشد.
3. **هر اقدام حساس → AuditLog**.
4. **هر لیست → صفحه‌بندی** (inline).
5. **هر پیام خطا → پیام فارسی قابل‌فهم + راه بازگشت**.
6. **هیچ رمز/توکنی در لاگ نرود.**

## ۵) امنیت و انطباق

| موضوع | راهکار |
|---|---|
| توکن | فقط `.env` (git-ignored) |
| رمز عبور | هرگز ذخیره نمی‌شود؛ پیام حذف می‌شود |
| تلاش ورود | قفل ۱۰ دقیقه بعد از ۵ خطا |
| نشست | `/logout` + انقضای اختیاری |
| نرخ پیام | حداکثر ۳۰ پیام در دقیقه برای هر حساب |
| اقدامات مدیر | AuditLog با actor/target/time |
| دسترسی | `is_admin_mode` + نقش دوگانه |
| دادهٔ حساس | بدون ارسال رمز/توکن در لاگ |

## ۷) ریسک‌ها

| ریسک | کاهش |
|---|---|
| قطعی API بله | retry + backoff + لاگ + سرویس restart |
| پیام تکراری بعد از قطعی | offset در `BotState` |
| سوءاستفاده/اسپم | rate limit + قفل ورود |

| تغییر کد هنگام اجرا | `update.sh` ربات را ری‌استارت می‌کند |
